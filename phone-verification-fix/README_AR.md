# إصلاح تأكيد رقم الهاتف فقط — ١٥ أكتوبر ٢٠٢٦

الرسالة «تعذر تهيئة التحقق. أعد المحاولة» كانت تصدر من تطبيق أندرويد عندما لا يجد رمز حماية داخل صفحة HTML، قبل إرسال رمز واتساب للتحقق. الصورة وحدها لا تثبت هل الصفحة أعادت توجيه الطلب أو حُجبت أو انتهت جلستها.

ينقل هذا الإصلاح تأكيد الهاتف وإعادة إرسال الرمز إلى JSON في نطاق `/api/`، بنفس جلسة التسجيل. يقرأ الحساب والرقم من الجلسة المعلقة حصراً، ويبقي فحص الرمز وصلاحيته وحدود المحاولات وإعادة الإرسال وحماية الجهاز في وظائف الموقع الموجودة. لا يحتاج مفاتيح جديدة أو استيراد SQL.

## التركيب

١. ارفع الملف الوحيد `public_html/api/verify-phone.php` إلى مجلد `public_html/api/` في موقعك. إعداداتك الحالية في `config` تبقى كما هي.

٢. ثبّت ملف أندرويد الموقّع `Murshid_Android_v4_8_30_Build49814_PHONE_FIX_SIGNED.apk` فوق التطبيق الحالي. هذه النسخة مبنية على 4.8.28 / Build 49812، مع إصلاح تأكيد الهاتف فقط وزيادة رقم الإصدار للسماح بالتحديث.

٣. افتح تسجيل الدخول بنفس رقم الهاتف وكلمة المرور اللذين استُخدما لإنشاء الحساب. لا تنشئ حساباً جديداً. أكمل تأكيد الهاتف؛ إذا انتهت صلاحية رمز واتساب القديم اطلب رمزاً جديداً من الشاشة نفسها.

٤. لا تستخدم حزمة مراجعة الأسئلة أو تصحيحات SQL أو حزمة الخادم السابقة لهذا الإصلاح. لا يلزم تحديث الآيفون لمعالجة المشكلة المصوّرة في تطبيق أندرويد.

## التحقق وحدوده

يشمل التحقق عقد نقطة PHP الفعلية مع جلسات معزولة، واختبارات أندرويد وبناء APK، ومسار تسجيل هاتف افتراضي على محاكي: بقاء Cookie التسجيل، منع الدخول بالرمز الخاطئ، رسائل الجلسة المنتهية، مهلة إعادة الإرسال، تجديد CSRF، ثم الدخول بالرمز الصحيح بعد تبديل Cookie الجلسة. صفحات HTML القديمة تُحجب في الاختبار عمداً للتأكد من أن التأكيد لا يعتمد عليها.

المزود الخارجي لرسائل واتساب لم يتغير. اختبارات الإصلاح تستخدم حسابات ورموزاً اصطناعية؛ لم تُرسل رسائل إلى هواتف فعلية، ولم يُرفع الملف إلى استضافتك. إذا كانت حماية الاستضافة تمنع حتى `/api/verify-phone.php`، يلزم فحص سجل الحماية لهذا المسار؛ لا تُعطّل حماية الموقع بالكامل.
