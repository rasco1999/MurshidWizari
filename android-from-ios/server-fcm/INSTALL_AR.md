# إعداد FCM لتطبيق Android Native v4.9.16

**المعرّف الصحيح:** `com.muriq.murshid.iosparity` (وليس `com.murshidwizari.student` المستخدم في النسخة التجريبية القديمة).

هذا التحديث يدعم المعرّفين معًا دون حذف تسجيلات الأجهزة القديمة. عندما يطلب تطبيق Compose إعداداته باستخدام `?package=com.muriq.murshid.iosparity`، يختار الخادم إعداد Firebase المطابق له. يبقى التطبيق القديم يستخدم إعداداته الافتراضية.

## تركيب آمن

1. **لا ترفع الحزمة مباشرة فوق الخادم قبل أخذ نسخة احتياطية** من ملفي `includes/android_fcm.php` و`mobile/android-push-config.php` الحاليين.
2. أنشئ في مشروع Firebase تطبيق Android آخر باسم الحزمة الجديدة. احتفظ بالتطبيق القديم في مشروع Firebase نفسه، إذا كنت تستخدمه. وفّر `google-services.json` يحتوي تعريف تطبيق Compose (وتعريف التطبيق القديم إذا استمر مستخدمًا).
3. ضع `google-services.json` و`firebase-service-account.json` في مجلد `murshid-private` خارج `public_html`، وفق صلاحيات استضافتك. **لا تضع ملف حساب الخدمة في GitHub أو التطبيق أو مجلد عام.**
4. قبل النشر، قارن تعديلات `includes/android_fcm.php` و`mobile/android-push-config.php` مع نسختك الحية. يتضمن هذا المجلد أيضًا الملفات الأخرى الضرورية إذا لم تكن مركبة أصلًا.
5. في بيئة اختبار ذات قاعدة بيانات اختبارية فقط: `php tests/config_parity.php`. وبعد اكتمال إعداد قاعدة الإنتاج، يمكن لمسؤول الاستضافة تشغيل `php system/android-fcm.php --check`. إعداد Cron والجدول موضّح في التعليمات القديمة الخاصة بالخادم.
6. **لا تستبدل `mobile/logout.php` من نسخ قديمة**؛ احتفظ بجلسات الدخول والتحقق الحديثة. يعتمد الفصل النهائي على مسار تسجيل الخروج الحالي وتكامل إلغاء رمز الجهاز.

## نطاق التحقق

اختبارات PHP الثابتة واختبار اختيار المعرّفين لا ترسل رسائل حقيقية. لن تعمل الإشعارات الفورية حتى تتوفر صلاحيات Firebase ومفاتيحه، ويدخل جهاز الطالب برمز FCM صحيح، وتعمل مهمة الإرسال في الاستضافة. تنبيهات إعلان المدرسة في التطبيق الجديد ما زالت تمتلك مسار WorkManager احتياطيًا (غير فوري). **تحويل حدث نشر الإعلان إلى إشعار FCM خاص به يحتاج إلى اختبار وتوصيل خادم الإنتاج، ولم يُعتمد بعد.**
