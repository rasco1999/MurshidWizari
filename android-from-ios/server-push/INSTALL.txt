Android 4.9.15 FCM server integration: INSTALLATION GUIDANCE

DO NOT UPLOAD THESE FILES BLINDLY. This package is separate from the production
site. It targets Android app ID com.muriq.murshid.iosparity and must be merged
with the current public_html only after backup. It contains NO real credentials.

1. Add Android app com.muriq.murshid.iosparity to your own Firebase project.
2. Download google-services.json and create a matching FCM HTTP v1 service
   account JSON with the required IAM permission. Store both OUTSIDE
   public_html in ../murshid-private with restrictive filesystem permissions.
   Never include the service account in the APK or GitHub repository.
3. Back up production database and site. Add PHP includes/android_fcm.php,
   includes/android_school_fcm.php, mobile/android-push-config.php,
   mobile/fcm-register.php, system/android-fcm.php from the public_html folder.
   If another Android FCM module already exists, do not overwrite it:
   a dual-package compatibility migration must be planned first.
4. CLI setup: php system/android-fcm.php --install
   CLI check: php system/android-fcm.php --check
5. Configure cron once per minute:
   php /ABSOLUTE/PATH/public_html/system/android-fcm.php --dispatch
6. The preexisting site logout endpoint must be merged to revoke devices
   with android_fcm_revoke() after authenticated CSRF validation. This file
   is NOT included because it could overwrite more recent changes.
7. Send a NEW school announcement with a verified test account, wait for
   cron and inspect mobile/notifications.php plus Android notifications.
   This has not been live-tested. The independent WorkManager fallback remains.

Existing active school ads are not sent as retroactive notifications on
first installation. Cron recognizes future scheduled ads and updates.
