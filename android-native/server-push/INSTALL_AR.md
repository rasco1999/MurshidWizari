# ربط إشعارات Android بحساب الطالب

هذه الحزمة تضيف قناة Firebase Cloud Messaging مستقلة عن إشعارات المتصفح. لا تحتوي أي كلمة مرور أو مفتاح Firebase حقيقي، ولا تغيّر الدفع أو بنك الأسئلة. APK الإصدار 4.8.18 برقم Android الداخلي 49802 يجلب الإعداد العام من خادم المنصة؛ لذلك لا يحتاج إعادة بناء لمجرد إضافة إعداد Firebase لاحقًا.

## الإعداد المطلوب من مالك المشروع

1. في مشروع Firebase الذي تملكه، سجّل تطبيق Android باسم الحزمة `com.murshidwizari.student` ونزّل ملف `google-services.json` الخاص به.
2. فعّل Firebase Cloud Messaging API (HTTP v1). أنشئ حساب خدمة بصلاحية إرسال FCM للمشروع نفسه، واحفظ ملفه باسم `firebase-service-account.json`.
3. ضع الملفين في مجلد `murshid-private` بجانب `public_html`، وليس بداخله. اجعل صلاحيات المجلد 700 والملفين 600. يمكن تغيير المسار بمتغير البيئة `MURSHID_FCM_PRIVATE_DIR`. لا تضع ملف حساب الخدمة في التطبيق أو GitHub أو رابط عام.

## تركيب ملفات الخادم

- خذ نسخة احتياطية من `mobile/logout.php` الحالي. ارفع محتويات مجلد `public_html` في هذه الحزمة إلى مجلد الموقع نفسه. الملفات الجديدة ثلاثة: `includes/android_fcm.php` و`mobile/android-push-config.php` و`mobile/fcm-register.php`، ومعها أداة `system/android-fcm.php`. ملف الخروج المرفق مبني على نسخة الموقع التي أرسلتها في 11 أكتوبر؛ يضيف فصل الجهاز ويحتفظ بتحرير الجلسة الحالية.
- من Terminal الاستضافة، داخل مجلد `public_html`، شغّل:

```bash
php system/android-fcm.php --install
php system/android-fcm.php --install-hook
php system/android-fcm.php --check
```

الأول ينشئ جدول أجهزة Android فقط. الثاني يضيف الاستدعاء إلى دالة `notify_user` الموجودة ويحفظ نسخة خاصة من الملف؛ يرفض التعديل إن اختلف موضع الدالة. الثالث يتحقق من إعداد التطبيق والجدول وتفويض Google، ولا يرسل إشعارًا.

أضف مهمة Cron كل دقيقة بالأمر التالي بعد استبدال مسار مجلد الموقع بمسارك الحقيقي:

```bash
php /FULL/PATH/public_html/system/android-fcm.php --dispatch
```

يبقى Cron لازمًا للمحاولات المؤجلة، وللاستضافات التي لا تتيح الإرسال بعد إنهاء استجابة PHP. جميع أوامر الأداة متاحة من CLI فقط؛ فتحها كرابط لا ينفّذ شيئًا.

## السلوك والاختبار النهائي

- الإذن من Android مطلوب لعرض التنبيهات. يظل صندوق الإشعارات يعمل عند الرفض أو غياب Google Play Services.
- التطبيق يسجل رمز الجهاز بعد التحقق من جلسة الطالب. يغيّر ارتباط الإشعارات عند تبديل الحساب، ويمسحه عند الخروج أو انتهاء الجلسة. فصل رمز الخادم يحدث مع مسار الخروج المحدّث.
- الإرسال يحمل رقم إشعار ومعرّف ارتباط عشوائي فقط؛ نص الرسالة وبيانات الطالب تبقى في الصندوق المحمي. اضغط التنبيه لفتح الصندوق بعد تسجيل الدخول وفتح البصمة عند تفعيلها.
- الرموز المتبدلة تُحدَّث، والمكرّر يُتجاهَل، وFCM `UNREGISTERED` يُحذف. الخطأ المؤقت لا يستهلك الإشعار، مع تراجع زمني واحترام `Retry-After`. حساب آخر لا يستطيع فصل الارتباط الحالي باستخدام معرّف مستخدم قديم.
- بعد نجاح `--check`، سجّل دخول حساب الاختبار في هاتف Android واسمح بالإشعارات. أنشئ إشعارًا لذلك الحساب من مسار الإدارة المعتاد، وانتظر تشغيل Cron، ثم تحقق من وصوله في الخلفية وفتح الصندوق. اختبر الخروج وتبديل الحساب. إرسال رسالة Notification مباشرة من Firebase Console يتجاوز تصميم الإشارات المعتمد هنا؛ استخدم مسار الخادم هذا للاختبار.

## ما تم وما لم يتم التحقق منه

اختبارات قاعدة البيانات وواجهة Android تستخدم بيانات اصطناعية. لم تُوفَّر إعدادات Firebase الحقيقية في الملفات الحالية، ولم تُرفع الحزمة إلى الاستضافة من هذه الجلسة، لذلك لا يوجد دليل وصول فعلي من FCM بعد. اختبار الدفع هنا يستخدم بوابة محلية لا تستقبل أموالًا. نجاح البصمة على الهاتف يحتاج جهازًا مسجّلًا ببصمة صاحبه.

المراجع: [عميل FCM](https://firebase.google.com/docs/cloud-messaging/android/get-started)، [استقبال الرسائل](https://firebase.google.com/docs/cloud-messaging/android/receive-messages)، [تفويض HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).
