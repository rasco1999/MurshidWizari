# المرشد الوزاري — Android Native

تطبيق Android أصلي بلغة Kotlin، دون WebView، يُبنى من فرع `android-native`.

## Implemented in the Android prototype
- Login, remembered sessions encrypted by Android Keystore, password visibility.
- Native home, subjects, topics, exams, registration form, account, notifications, favorites, review, stories, support, subscription code and predictions screens.
- RTL layout and manually selectable dark/light colors.
- Exam answers submitted to the PHP server with confirmation required before advancing; no automatic retry after an ambiguous timeout.
- Native Daily Challenge GET/POST (`mobile/challenge.php`) with full-form validation, one-time submission, server-authoritative grading and an uncertain-request recovery gate.
- Million Contest and seasonal leaderboards (`mobile/contest.php`, `mobile/season.php`) with rank details and actions to earn XP, plus Achievements (`mobile/achievements.php`) with earned/locked filtering and paths back to studying. No client-side XP/badge awarding.
- Account: server-validated three-part name edit (including Unicode whitespace/direction normalization), refreshed profile/bootstrap after mutation, JPEG compression/resizing/EXIF rotation for selected images, bounded multipart avatar upload, immediate successful-upload preview, revision-aware uncached avatar display and direct removal; subscribed/remaining state never inferred from a local button.
- Subscription: interactive plan selection, externally opened HTTPS checkout, account-scoped persisted payment order ID, explicit and on-return payment status check. Unlocking subscribed features requires confirmed server bootstrap; requests with uncertain outcome are not auto-resubmitted.
- Brand tokens aligned with the SwiftUI navy `#0B1F33`, blue `#2D6CDF`, gold `#F5B83D`; 17dp gradient/ripple buttons with press animation and profile gradient card. The updated UI follows the owner's **iOS 4.8.18 screenshots**, uses a five-tab bar (home/tests/predictions/ads/account), native line icons, grouped cards and two-column tools on phones. The home quick-tool grid includes only the eight options visible on iPhone, followed by mistake-analysis and social-links sections. The account screen has iOS-style sections and a native platform-instructions page. Android 15 safe insets are applied. **This is code-level layout alignment, not proven pixel-perfect parity.**
- The Android launcher and fallback profile emblem now use the **actual golden-mosque phone icon `AppIcon60x60@2x.png` extracted from the GitHub iOS v4.8.18 Build498 IPA**, not an earlier unrelated 1024×1024 JPEG. The extracted icon has SHA-256 `c9111c86a08bc88f3a198b7ece7b012d923b922f62ad46f56108a0fa916c077f`; actual Android mask/crop remains to be compared on a device.
- Successful answer grading shows the inline feedback/explanation card without displaying a second system AlertDialog; the app's selected light/dark style now applies to system dialogs as well. Direct iPhone/device comparison is still required.
- Account security now includes a **real native biometric prompt** (Android face/fingerprint where supported, fingerprint fallback on Android 8), gated by an actual successful enrollment/authentication before turning on. Re-entering the app after more than 20 seconds in the background places a full-screen lock over account content until authentication; cancelling does not unlock it. A native **daily study reminder** lets the user enable/disable notifications and choose a local device time (19:00 default, matching iOS SwiftUI), with a reschedulable inexact Android alarm, notification channel, Android 13+ runtime permission and reboot/time-zone restoration. These are device-level features and remain subject to hardware, OS notification limits and physical-device QA.
- The account's visible service/security rows now follow the owner's **current v4.8.18 account screenshot**: name edit (when allowed), notifications, support; biometric lock, daily reminder, password recovery. The older iOS V31 school-ad/stories rows remain available via their existing functional routes, but are no longer shown as extra account menu items. Platform instructions remain accessible before login, matching the checked-in iOS guest view.
- The ordinary topic exam now uses an iOS-style progress header, a separate ministerial-question card, a grouped answer-options card, clearly separated server feedback/explanation and a fixed previous/next footer. Progression still requires the server to acknowledge the submitted answer. Specialized matching/calculation/genetics inputs retain their existing native controls pending screenshot-level audits.
- Android validated connectivity callbacks, differentiated timeout/offline/security messages, explicit retry/restore remembered session and stale-session callback suppression. A rotated exam keeps the active in-memory answers.
- Native password recovery based on the iOS HTML form contract: fetches same-origin CSRF safely, starts email/phone recovery, accepts the 64-character WhatsApp reset token, supports six-digit OTP + password confirmation, allows resend and clears login cookies on confirmed password change. No WebView or automatic re-submission after a timeout.
- Interactive study plans (`mobile/study-plan.php`): list saved plans and create a server-backed plan with native day/target steppers matching iOS bounds; network-ambiguous creation is not automatically repeated.
- Native school-advertisement request: school name, full ad text, 1–90-day stepper, confirmation, then an internal support message sent to `mobile/support.php`, with no repeated POST on ambiguous failure.
- Favorite-question list now includes correct answers and explanations and allows removing an item through the existing question-tools endpoint.
- Search queries to `api/search.php` now render actual matching question/topic results; review includes weak-topic rates and counts; notifications show unread state/timestamps.
- Server-backed custom-exam attempt history lists completed scores. Focus sessions use the real `mobile/study-session.php` start/finish requests, a wall-clock timer with 25/45/60-minute selections, account-scoped local recovery on return and explicit reconciliation of uncertain POSTs.
- Full native custom-practice builder (`mobile/practice.php`): subject/topic selection, 5–50 question count, six type filters, five answer-state filters and optional timer; interactive question navigation and input, account-scoped recovery of unanswered input and elapsed time, single server-side final correction with score/incorrect answers/explanations. Create/finish requests never auto-retry after ambiguous outcomes.
- Student question proposals (`mobile/question-submit.php`) now accept native subject/topic and question-type selection, validated options/answer, explanation, source and exam metadata, and send to the content reviewers; a separate native requests screen tracks server review statuses and admin notes.
- Registration now supports both Iraqi mobile/WhatsApp and email contact methods, adds the gender control to the visible form, validates full names/identifiers/passwords, and passes the iOS-compatible server payload. Email and phone six-digit verification and resend now run natively through the existing CSRF-protected PHP forms.
- Home and form buttons now wrap across up to three lines and measure their own height, protecting long Arabic labels from clipping at larger system font scales and on narrow phones.
- Live unauthenticated read-only server checks: `mobile/bootstrap.php` and `mobile/account.php` returned HTTP 401 as expected; `api/grades.php` returned HTTP 200 with grade JSON. These are **not** authenticated integration tests.
- JVM regression tests for question quality, answer progression, challenge rules, account/network/recovery validation and study-plan/ad-request boundaries. GitHub Actions runs them before building the APK.
- Correct Android back navigation and both object/string multiple-choice formats.
- Debug APK build and artifact upload via GitHub Actions.

## Release blockers — do not distribute as production
1. **Authenticated server compatibility has not been verified on a real device.** The latest iOS API client and Android both call `api/login.php` with JSON. Validate login cookies, CSRF, avatar revision, account name change, checkout callbacks, order status and all authenticated response schemas with a dedicated test account before claiming parity.
2. Confirm the server's answer grading/credit semantics with a **test account**; in particular whether `api/progress.php` acknowledges `grades` and prevents duplicate quota charges.
3. Verify registration, account recovery, subscription code, payment, avatar upload, notifications, question formats, daily challenge award/quota behavior, contest leaderboard response schemas and errors with a deployed **test account**. Some Android screens are provisional and may require server changes.
4. Test on multiple physical Android devices, slow mobile data and offline transitions; verify accessibility, RTL, API timeouts, **biometric enrollment/cancellation/return lock**, Android 13+ notification permission, reminder delivery and after-reboot scheduling. The local reminder is **not** a replacement for FCM/APNs server push.
5. Compare all screens, assets, fonts, icons, motion, RTL and flows against the iOS 4.8.18 IPA on phone/tablet screenshots. The system Android Arabic fallback font is **not** Apple's SF Arabic, and the custom vector icons are approximations of SF Symbols. Owner-provided iPhone and Android screenshots revealed concrete discrepancies and motivated the icon/home/dialog fixes, but a fresh APK/device recheck is still needed. The app is **not pixel-perfect**.
6. Final release APK requires the owner's private signing keystore and credentials. `assembleRelease` / `bundleRelease` are gated by `verifyReleaseSigning`: `MURSHID_RELEASE_KEYSTORE`, `MURSHID_RELEASE_STORE_PASSWORD`, `MURSHID_RELEASE_KEY_ALIAS`, and `MURSHID_RELEASE_KEY_PASSWORD` must be supplied securely. The key and secrets must never be committed. Do **not** run or distribute the signed build until the full functional/server/device audit passes.

**Safety:** Do not commit passwords, signing keys, private student data or server database exports. Do not modify production database or grant credits while testing.
